**Direct hardware access can now actually open an X22i's console.** This is the fix the last two releases were reaching for and missing.

Stride would only talk to a console over a USB pipe of one particular kind. An X22i's controller board presents itself as a HID device, which uses a different kind — so Stride looked at a board that was plugged in, powered, enumerated and already permitted, decided there was nothing there, and reported "No direct connection to the treadmill." No protocol work could ever have been reached, because the connection was never opened.

Diagnosed on real hardware and fixed by **@knaackville**, who pulled the console's own USB descriptor to prove it rather than inferring it. Thank you.

**Stride now says what it found, down to the pipes.** Settings reports the console on the port, whether Android has granted access, and the data pipes it offers — or says plainly that it found none it can use. The whole reason this took three releases is that every one of those situations produced the same sentence.

**Tapping the connection you are already on now retries it.** Previously that tap did nothing, which is exactly the wrong behaviour for a rider whose machine was switched on, plugged in, or granted permission after the last attempt failed — the one row they would think to press was inert.

**Still not confirmed working end to end.** Opening the connection is what changed here. Whether the controller then answers Stride's handshake is the next thing to find out, and the settings screen is now detailed enough to say. If it does not connect, that line is what to send.

**The safety key is still the only emergency stop**, on every connection. Nothing here changes what protects you.

Installs as an update over 1.2.1.

Tested on a NordicTrack Commercial 1750; the USB fix is verified against a NordicTrack X22i's own hardware descriptor.
