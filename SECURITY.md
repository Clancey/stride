# Security Policy

## Reporting a vulnerability

**Do not open a public issue.** Use GitHub's private vulnerability reporting:
the **Security** tab of this repository → **Report a vulnerability**. That opens a
private advisory visible only to the maintainers.

Please include the console model and firmware, the Stride version (Settings → About,
or the `versionCode` from the catalog), what you observed, and the steps to reproduce.

This is a solo, unfunded project. There is no paid bounty and no guaranteed response
window, but reports are read and credited unless you ask otherwise.

## Safety defects outrank security bugs

A treadmill is the one component in this project that can physically hurt someone,
so please treat these as the highest severity and report them the same private way:

- The belt does not stop when Stride reports it stopped.
- The UI claims "stopped" without a confirming ack *and* observed deceleration.
- Stride interferes with the physical safety key, or the hardware interlock fails
  to cut the belt with Stride running as launcher.
- A speed or incline clamp can be exceeded, or a stop is ramp-limited or queued
  behind another command.
- The console starts the belt without an explicit user action.

**The physical safety key is the only true emergency stop.** Stride's software stop
is a best-effort convenience and is documented as such — see the Safety section of
`README.md` and `docs/PLAN.md` §5. A report that Stride's software stop is not a
fail-safe is not a vulnerability; it is the documented design.

## Out of scope — deliberate, documented decisions

Please do not file these; they are known and intentional, and each is argued in the
docs rather than left to chance.

**The bundled mTLS credentials** in `apps/spikes/android/app/src/main/assets/glassos/`
are committed on purpose. They are not a per-device identity and not a secret: one
fixed keypair generated by iFit opens every console of this generation, it already
ships inside several publicly distributed apps, it authenticates only to a
loopback-only service (`127.0.0.1:54321`) on hardware the operator already owns, and
it grants access to no remote account. See the Credentials section of `README.md`
and `docs/PLAN.md` §2.2. Automated secret-scanner hits on the bundled `client_key.pem`
are expected and will be closed as such.

**Hostname verification is disabled for the GlassOS connection.** The console's
server certificate is `CN=localhost` with no subjectAltName, which modern TLS stacks
reject outright. Stride verifies the full certificate *chain* against the pinned CA
and skips only the hostname match — it does not trust all certificates. The endpoint
is loopback, so the connection cannot leave the device, and an attacker able to bind
loopback on the console already has code execution there. See the reasoning in
`apps/spikes/android/app/src/main/kotlin/io/stride/spikes/GlassOsCredentials.kt`.

**The release keystore ciphertext** at `keystore/stride-release.jks.enc` is committed
by design; the passphrase and the decrypted key are not. See `docs/SIGNING.md`.

## In scope

Things genuinely worth a private report:

- Anything that lets a *remote* or non-loopback party reach the machine control path.
- Privilege escalation through Stride's accessibility service, overlay, or its
  `WRITE_SECURE_SETTINGS` grant.
- The background updater (`docs/APPSTORE.md`) installing an APK whose signature or
  catalog entry was not verified, or a downgrade/rollback that bypasses that check.
- Leakage of user credentials, workout data, or machine serial numbers into logs,
  `/sdcard`, committed traces, or any network destination.
- Recovery of the release signing key or its passphrase from anything committed here.

## Supported versions

Only the most recent release in the
[catalog](https://github.com/Clancey/stride-catalog) is supported. Consoles update
themselves over the air, so "upgrade to current" is the normal remediation.

## A standing caveat

Stride has been tested on exactly one machine: a NordicTrack Commercial 1750. Other
iFit consoles run the same Android software and will probably work, but nobody has
verified it. Reports from other hardware are welcome — read `docs/RUNBOOK.md` and
verify the revert path before you make yourself the first.
